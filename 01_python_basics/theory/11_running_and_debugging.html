Running and Debugging Python

Running a program means asking Python to execute a .py file. Debugging means finding and fixing the reason a program does not work as expected.

Run a program in UCRT64

Open the MSYS2 UCRT64 terminal in your project folder. If your file is named load_check.py, run:

python load_check.py

To confirm that you are using the intended Python installation, run which python and python --version first. On Windows, use the UCRT64 terminal for this course rather than Command Prompt or PowerShell.

Read output carefully

# load_check.py
load_kn = 12.5
limit_kn = 10

if load_kn > limit_kn:
    print("Warning: load exceeds the limit.")
else:
    print("Load is within the limit.")

Expected output: Warning: load exceeds the limit. because 12.5 is greater than 10. Testing with a known input is the first debugging step.

What a traceback tells you

When Python cannot continue, it prints a traceback. Read it from the bottom up: the last line names the error and its message. Earlier lines show where the error happened.

Traceback (most recent call last):
  File "load_check.py", line 3, in <module>
    pressure_pa = load_n / area_m2
NameError: name 'load_n' is not defined

Explanation: line 3 uses load_n, but that name was never created. Check spelling and make sure the assignment appears before the use.

Use small print checks

force_n = 1000
area_m2 = 0

print(f"force_n = {force_n}, area_m2 = {area_m2}")
if area_m2 == 0:
    print("Cannot calculate pressure: area is zero.")
else:
    print(force_n / area_m2)

Expected output: the variable values print first, followed by the clear zero-area message. This avoids a ZeroDivisionError and reveals the bad input.

Common beginner errors

  • SyntaxError — Python cannot read the code, often because of a missing colon, quote, or bracket.
  • IndentationError — a block after if, for, while, or def is not indented correctly.
  • NameError — a variable or function name is misspelled or has not been created.
  • TypeError — an operation used incompatible types, such as adding text and a number.
Fix the first reported error, save the file, and run it again. One syntax error can cause several later-looking messages.
Never hide errors with a broad except: while learning. Read the traceback first; it contains the evidence needed to fix the cause.

Try it yourself

Create debug_load_check.py with a load and limit. Print both values with an f-string, then print either PASS or FAIL. Run it in UCRT64 with python debug_load_check.py. Change one variable name on purpose, read the traceback, then fix it.
