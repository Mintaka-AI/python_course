Dataclasses, Enums, and Dunder Methods

Lesson 17 · Clear data objects and fixed choices for engineering programs

Prerequisite: know classes, methods, attributes, strings, and lists. A dataclass is still a class; it simply writes some common class code for you.

Why use a dataclass?

A beam test has related values: an ID, a load, and a result. Keeping them together in an object is clearer than passing three separate variables. The @dataclass decorator automatically creates a useful __init__, __repr__, and equality comparison.

from dataclasses import dataclass

@dataclass
class BeamTest:
    test_id: str
    load_kn: float
    passed: bool = False

test = BeamTest("B-17", 24.0, True)
print(test)

Expected output: BeamTest(test_id='B-17', load_kn=24.0, passed=True). Fields with default values must come after required fields.

Enums: a small set of named choices

An Enum prevents unclear status text such as "pass", "Passed", or "yes". Use its member name in code and its value when displaying data.

from enum import Enum

class TestStatus(Enum):
    PLANNED = "planned"
    PASSED = "passed"
    FAILED = "failed"

status = TestStatus.PASSED
print(status)
print(status.value)

Expected output: TestStatus.PASSED, then passed.

Dunder methods

“Dunder” means double underscore. Python calls these special methods for common operations. A dataclass supplies several of them, but you can customize them.

  • __init__ runs while an object is created.
  • __str__ returns a friendly string for print(object).
  • __repr__ returns a detailed developer representation.
  • __eq__ decides what object_a == object_b means.
def __str__(self) -> str:
    return f"{self.test_id}: {self.load_kn:.1f} kN"

After this method, print(test) can show B-17: 24.0 kN.

Warning: an enum is not the same as an arbitrary string. Compare with TestStatus.PASSED, not with "PASSED". Do not put validation or complicated calculations inside __str__; printing should be safe and quick.
