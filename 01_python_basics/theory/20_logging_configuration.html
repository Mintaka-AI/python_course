Logging and Configuration

Lesson 20 · Useful program records without leaking secrets

Prerequisite: know functions, imports, exceptions, and strings. Use print() for short learning output; use the standard logging module when a program needs consistent diagnostic records.

Logging levels

A level describes the importance of a message. This lets operators filter routine messages from failures.

  • DEBUG: detailed developer investigation.
  • INFO: normal progress, such as starting a calculation.
  • WARNING: work continues, but attention may be needed.
  • ERROR: one operation failed or produced an unsafe result.
  • CRITICAL: the program may be unable to continue safely.
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(levelname)s %(name)s: %(message)s",
)
logger = logging.getLogger("beam_monitor")

logger.info("Starting load check")
logger.warning("Sensor calibration is overdue")

Expected output: lines similar to INFO beam_monitor: Starting load check and WARNING beam_monitor: Sensor calibration is overdue.

Use environment variables for configuration

An environment variable is a value supplied outside source code. It is suitable for deployment-specific settings, such as a project name, endpoint, or secret token. Read it with os.getenv().

import os

project_name = os.getenv("PROJECT_NAME", "local-beam-study")
token = os.getenv("DEMO_API_TOKEN")

if not token:
    raise RuntimeError("Set DEMO_API_TOKEN before external upload.")

The second argument of getenv is a safe default. A secret token normally has no default, because uploading without one should not happen.

Log facts, never secrets

# Good: records that a token exists, not its value.
logger.info("Token supplied (%d characters); value hidden.", len(token))

# Never do this:
# logger.info("Token is %s", token)

Use logger formatting arguments instead of building a long f-string when logging. The logger can avoid formatting messages that will be filtered out.

Warning: do not put passwords, API tokens, connection strings, or private measurement data in source code, logs, screenshots, or commits. Treat log output as something another person may read.

Engineering example

The matching script configures an application logger, reads PROJECT_NAME, and disables an external-upload step when DEMO_API_TOKEN is absent. It intentionally never prints the token.

python examples/20_logging_configuration.py

Expected output without a token: an INFO start message, a WARNING that external upload is disabled, and an INFO load ratio of 84%.

Try it yourself

Make a logger named pump_monitor. Read PUMP_LIMIT_L_MIN from the environment with a safe local default of "120", convert it to a float, and log WARNING when a flow is above the limit. Ensure that no secret-like value is logged.
