Engineering Agent Patterns

An engineering agent is a program that selects steps toward a goal. Its most important safety pattern is separation: text can describe a plan, but a deterministic tool function performs numerical engineering calculations.

Prerequisite: understand functions, dictionaries, validation, and return values. This lesson uses a local simulation only: no network calls, external APIs, credentials, or secrets.

A simple local pattern

Request text
    ↓
Text planner chooses an allowed tool name
    ↓
Validator checks structured numerical inputs
    ↓
Deterministic tool calculates a result
    ↓
Formatter explains the result and limits

This is a flow diagram, not Python code.

The planner is not the calculator. It may choose calculate_pressure, but it must not invent the result. The tool receives numbers, applies one known formula, and returns a structured result.

Tool-function syntax

def calculate_pressure(force_n: float, area_m2: float) -> dict[str, float]:
    if force_n < 0:
        raise ValueError("force must be zero or greater")
    if area_m2 <= 0:
        raise ValueError("area must be greater than zero")
    return {"pressure_pa": force_n / area_m2}

The function has a narrow purpose and explicit units. Because it has no hidden state or network access, the same inputs always produce the same result.

Text planning is separate

def choose_tool(request_text: str) -> str:
    if "pressure" in request_text.lower():
        return "calculate_pressure"
    raise ValueError("No allowed local tool matches the request")

This small rule-based planner stands in for the text-planning part of an agent. A real language model may produce text, but application code must still validate the selected tool and every argument before calling it.

Run the local pattern

def calculate_pressure(force_n: float, area_m2: float) -> dict[str, float]:
    if force_n < 0:
        raise ValueError("force must be zero or greater")
    if area_m2 <= 0:
        raise ValueError("area must be greater than zero")
    return {"pressure_pa": force_n / area_m2}

def choose_tool(request_text: str) -> str:
    if "pressure" in request_text.lower():
        return "calculate_pressure"
    raise ValueError("No allowed local tool matches the request")

request_text = "Calculate pressure"
tool_name = choose_tool(request_text)

if tool_name == "calculate_pressure":
    result = calculate_pressure(12_000, 0.006)
    print(f"Pressure: {result['pressure_pa']} Pa")

Expected output: Pressure: 2000000.0 Pa. This complete local example is runnable as written.

Guardrails for engineering tools

  • Allow only known tool names; never execute text as Python code.
  • Validate types, units, ranges, and required values at the tool boundary.
  • Keep calculation inputs and results structured, for example dictionaries.
  • Record assumptions such as units and safety factors in the final report.
  • Ask a qualified engineer to review safety-critical decisions.
Warning: text is not evidence. An agent's explanation can sound confident while being wrong. Do not expose secrets to prompts or tool functions, do not allow arbitrary commands, and do not use a teaching calculation as authorization for a real design decision.
