Object-Oriented Programming Basics

Prerequisite: understand dictionaries, functions, parameters, and return. Object-oriented programming (OOP) groups related data and behavior; it does not replace simple functions where a function is clearer.

A class is a blueprint. An object, also called an instance, is one thing made from that blueprint. For example, a Sensor class describes what every sensor has and can do; each physical sensor is an object.

Classes, objects, attributes, and methods

Values stored on an object are attributes. Functions inside a class are methods. The first parameter of an instance method is usually named self; it refers to the particular object using the method.

Syntax

class ClassName:
    def __init__(self, value):
        self.value = value

    def method_name(self):
        return self.value

Initialize an object with __init__

Python calls __init__ when you create an object. Use it to give every object its starting data.

class Sensor:
    def __init__(self, sensor_id, offset_c=0.0):
        self.sensor_id = sensor_id
        self.offset_c = offset_c

    def calibrate(self, raw_c):
        return raw_c + self.offset_c

sensor_a = Sensor("A-01", offset_c=0.2)
print(sensor_a.sensor_id)
print(sensor_a.calibrate(20.0))

Expected output:

A-01
20.2

Inheritance and composition

Inheritance means a more specific class starts from an existing class. Composition means an object contains another object. Prefer composition when objects simply work together; it often makes engineering software easier to change.

class Location:
    def __init__(self, room):
        self.room = room

class LocatedSensor(Sensor):
    def __init__(self, sensor_id, location):
        super().__init__(sensor_id)
        self.location = location

sensor_b = LocatedSensor("B-02", Location("Lab 3"))
print(sensor_b.sensor_id, "is in", sensor_b.location.room)

Expected output: B-02 is in Lab 3. LocatedSensor inherits from Sensor; it also contains a Location object.

Properties for controlled access

A property lets code read an attribute like a value while the class controls how it is calculated or checked. The @property decorator marks a method as a read-only attribute.

class Tank:
    def __init__(self, capacity_l, current_l):
        self.capacity_l = capacity_l
        self.current_l = current_l

    @property
    def fill_percent(self):
        return self.current_l / self.capacity_l * 100

tank = Tank(200, 50)
print(f"{tank.fill_percent:.0f}%")

Expected output: 25%.

Classes are helpful when data and the operations that protect or transform it belong together. A short calculation with a few inputs is often clearer as a normal function.
Safety note: an object is not automatically valid just because it exists. Check units and ranges in constructors or methods before using readings in a real decision. Do not rely on inheritance to bypass safety checks from a base class.
