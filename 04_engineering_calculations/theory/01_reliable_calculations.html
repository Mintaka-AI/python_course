Reliable Calculation Functions and Units

Learning goals

  • Write a calculation contract.
  • Validate domain restrictions.
  • Make conversions and assumptions explicit.
  • Use Pint for optional dimensional checks.

1. A calculation function is a contract

A reliable function states the meaning and units of inputs, the result unit, invalid conditions, and the model’s limits. These facts belong in names, validation, and the docstring.

def calculate_stress_pa(force_n: float, area_m2: float) -> float:
    """Return axial stress in Pa for a uniform force over a positive area."""
    if force_n < 0:
        raise ValueError("Force must not be negative.")
    if area_m2 <= 0:
        raise ValueError("Area must be greater than zero.")
    return force_n / area_m2

The formula is deterministic: the same valid inputs produce the same result. The docstring names the axial, uniform-load assumption.

2. Convert units at a visible boundary

def kilonewtons_to_newtons(load_kn: float) -> float:
    return load_kn * 1_000

force_n = kilonewtons_to_newtons(12.5)
stress_mpa = calculate_stress_pa(force_n, 0.0008) / 1_000_000

Explicit conversion functions prevent hidden constants from spreading through the program. Convert to one internal unit system, calculate, then convert for presentation.

3. Check dimensions with Pint

from pint import UnitRegistry
units = UnitRegistry()
force = 12.5 * units.kilonewton
area = 800 * units.millimeter**2
stress = (force / area).to("megapascal")
print(stress)

A Pint quantity contains magnitude and unit. Dividing force by area produces pressure dimensions; to converts the compatible result to MPa. An incompatible conversion raises an error.

4. State precision honestly

Rounding controls presentation, not measurement accuracy. Keep sufficient internal precision and round only the displayed result. Do not display more meaningful digits than the input data supports.

5. Verify with independent cases

Use hand-checkable values, boundary tests, and where appropriate a second independent method. Record formula source, revision, and assumptions in reports.

These examples teach software structure, not structural design approval. Real calculations require qualified review and relevant codes.
