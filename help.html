How to Study with an AI Instructor

Using Codex or Cline in VS Code with this course

← Course menu · Progress dashboard

The AI agent can act as a lecturer or as an instructor. A lecturer explains a topic. An instructor also asks questions, reviews your work, gives exercises, and updates state.json after assessment.

1. Open the correct folder in VS Code

Open the course root as the VS Code workspace:

C:/msys64/home/user1/projects/cources/python_cource1

This is important because the AI agent must be able to find:

  • AGENTS.md — the main instructor instructions;
  • state.json — your current progress;
  • Docs/plan.md — the course plan;
  • each module's theory/ and examples/ folders;
  • .cursor/rules/ and .cursor/skills/ — additional course workflow rules.
Do not open only one module folder. The agent needs the complete course root to read the instructions and update progress correctly.

2. Start the AI agent as an instructor

Open Codex or Cline in VS Code and start a new task or chat. Send this prompt:

Act as my instructor for this Python course.

Before teaching:
1. Read AGENTS.md.
2. Read state.json and Docs/plan.md.
3. Read the relevant rules in .cursor/rules/ and the course instructor skill.
4. Identify my current module from course.current_module.

For each lesson:
- open the next local HTML theory lesson in the internal browser;
- explain the theory in simple English and define every new term;
- show how the theory connects to the files in examples/;
- help me run examples in the MSYS2 UCRT64 terminal;
- explain the code step by step, but let me think and answer first;
- ask 2–4 understanding questions and wait for my answers;
- calculate my theory score after I answer;
- give me one practical task, review my solution, and provide hints before a full solution;
- update state.json only after an actual review, following Docs/state-schema.md;
- do not move to the next module until theory, examples, and code are all mastered.

Start by telling me my current module and the next lesson. Do not mark anything as mastered yet.

Short prompt for later sessions

Continue my Python course as the instructor. Read AGENTS.md and state.json first, then continue the current module from the next incomplete lesson.

3. Use lecturer mode when you only need an explanation

Lecturer mode is useful when you want to revisit a difficult topic without taking an assessment.

Act as a lecturer for this course. Read the current lesson and explain it in simple English with an engineering example. Open the local HTML lesson in the internal browser and explain the example code step by step. Do not assess mastery or update state.json in this session.

4. Open theory in the internal browser

Each module has a theory index, for example:

01_python_basics/theory/index.html
02_engineering_code/theory/index.html
06_engineering_ai_agents/theory/index.html

Ask the agent:

Open the current module's theory/index.html in the internal browser. Then open the next lesson and teach it to me section by section.

In Codex, the agent can open a workspace file in the built-in browser or file panel. In a VS Code setup where the agent cannot control a browser directly, use the Command Palette and run Simple Browser: Show, then paste the local URL supplied by the agent.

Direct file or local web server?

  • Individual theory pages can normally be opened directly as local HTML files.
  • The progress dashboard loads state.json with JavaScript. Browsers may block that request from a file:// page.
  • For the dashboard, start a local server and open its HTTP address.
cd /c/msys64/home/user1/projects/cources/python_cource1
python -m http.server 8000

Then open http://localhost:8000/index.html or http://localhost:8000/summary.html in the internal browser. Stop the server with Ctrl+C.

5. Configure the MSYS2 UCRT64 terminal

All course commands must run in MSYS2 UCRT64, not PowerShell, Command Prompt, MSYS, or MINGW64.

  1. In VS Code, open Terminal → New Terminal.
  2. Select the terminal profile named MSYS2 UCRT64.
  3. Navigate to the course root.
  4. Create and activate the virtual environment if it does not exist.
  5. Verify which Python executable is active.
cd /c/msys64/home/user1/projects/cources/python_cource1
python -m venv .venv
source .venv/Scripts/activate
python --version
python -m pip --version
which python

The result of which python should point to the course's .venv or to the UCRT64 Python installation.

6. Study an example with the agent

Do not ask only for the final output. Ask the agent to connect the example to the theory and make you predict what happens.

Open the example for this lesson. First explain its goal and inputs. Then walk through it in small sections and ask me what important lines do. Help me run it in the MSYS2 UCRT64 terminal. After it runs, explain the output and give me one small modification to make myself.

A typical run command is:

cd /c/msys64/home/user1/projects/cources/python_cource1/01_python_basics/examples
python 02_variables_and_types.py

For tests, follow the module README. A common command is:

python -m pytest test_file_name.py -q
If a package is missing, ask the agent to explain what it is and install it into the active course virtual environment with python -m pip install package-name.

7. Questions, exercises, and feedback

The instructor should use this order:

  1. Explain one theory topic.
  2. Ask 2–4 questions and wait for your answers.
  3. Score the answers. Theory is mastered at 75% or higher.
  4. Walk through a runnable example.
  5. Ask you to explain or modify the example.
  6. Give one practical coding task.
  7. Review your program by reading it and running appropriate checks.
  8. Update progress with specific notes.

If your answer is wrong, the instructor should explain the weak point differently and ask a new question. For a coding task, it should provide hints before giving complete code.

8. How state.json must be updated

state.json is the course record. The agent must read it at the beginning of every session and edit it only after an observable learning event.

Learning eventFields to update
Module startedstatus and course.last_session
Theory answers reviewedscore, mastered, attempts, last_checked, notes
Example explained or modifiedexamples.completed and the example review fields
Practical code reviewedcode.completed and the code review fields
All three blocks masteredComplete the module and move course.current_module forward

Required rules:

  • Increment attempts on every review.
  • Use an ISO 8601 date and time.
  • Write a specific note about strengths or gaps.
  • Preserve every module and field.
  • Keep valid JSON: double quotes and no trailing commas.
  • Do not mark theory, examples, or code as mastered without evidence.
Opening a lesson or running a supplied example is not enough to mark the whole module as mastered. Progress changes only after the corresponding review.

9. End-of-session prompt

Summarize what I studied today. Show my theory, examples, and code review results. Update state.json only for work you actually reviewed, validate that it is still correct JSON, and tell me the next incomplete step without starting a new module early.
