Agents, Tools, Schemas, and Action Logs

Learning goals

  • Explain the difference between a chatbot, an agent, and a workflow.
  • Design narrow deterministic tools.
  • Validate tool arguments and record an action log.

1. What is an AI agent?

In this course, an AI agent is a program in which a language model can decide what step to take and which declared tool to request. The surrounding Python application controls what is permitted, executes tools, returns their results, and decides when the process must stop.

A chatbot normally produces text. An agent can request actions. A workflow follows transitions designed in advance. Real applications often combine them: a model chooses among narrow options inside a deterministic workflow.

2. The agent loop

  1. Receive a user request.
  2. Decide whether it is supported and complete.
  3. Select an allowed tool or ask a precise question.
  4. Validate the proposed arguments and units.
  5. Execute a tested Python function.
  6. Return the structured result to the model.
  7. Verify, log, and explain the outcome.
  8. Stop at the answer or at a configured limit.

3. A narrow deterministic tool

def calculate_stress(force_n: float, area_m2: float) -> dict[str, float | str]:
    """Calculate uniform axial stress and return MPa."""
    if force_n < 0:
        raise ValueError("force_n must not be negative")
    if area_m2 <= 0:
        raise ValueError("area_m2 must be positive")
    return {
        "value": force_n / area_m2 / 1_000_000,
        "unit": "MPa",
        "formula": "stress = force_n / area_m2",
    }

The function name says what it does. Argument names include units. Type hints describe input shape. The docstring explains meaning. Validation rejects physically invalid values. The structured result can be tested and logged.

4. Schemas are contracts

A tool schema states its name, description, arguments, types, required fields, and sometimes ranges. It helps a model form a valid request, but it does not prove the request is safe or physically meaningful. Your Python function must check the inputs again.

5. Use an allowlist

TOOL_FUNCTIONS = {"calculate_stress": calculate_stress}

if requested_name not in TOOL_FUNCTIONS:
    return {"status": "refused", "reason": "Unknown tool"}
result = TOOL_FUNCTIONS[requested_name](**validated_arguments)

An allowlist prevents generated text from naming arbitrary functions, system commands, or file operations. Never evaluate model output with eval() or exec().

6. Missing data and failures are states

If the force is present but the area or its unit is absent, return needs_input and ask one question. Use invalid_input for bad values and refused for unsupported work. These states are easier to test than vague error prose.

7. Action logs and observability

Record time, selected tool, validated arguments, units, status, result, duration, and errors. Never log API keys or unnecessary sensitive data. A log explains what the software actually did; a model-generated explanation is not a substitute.

Tool access is authority. Give the agent only the tools, credentials, data, and network access required for its narrow purpose.
